# 슬라이스 10 — `EVAL.md`: 일치율 · 헛호출 · 실패 사례 분류 (2026-09-11)

실제 이름·경로는 여기 적지 않는다. 매핑은 로컬 전용 파일에 있다 (`ANONYMIZATION.md §5`).

```
npm run eval:coverage    # 반입한 241회차의 사유 문장을 분류해 커버리지와 헛호출 → data/eval/coverage.json
npm run import:incidents # 사고 사례를 익명화해 들여오고 원인 단계별로 분류 → data/eval/incidents.json
```

결과 문서는 [`EVAL.md`](../EVAL.md), 같은 표 넷을 화면으로는 `/eval` 에서 본다.

## 무엇을 했나

1. **분류표 하나** (`src/fleet/reasons.mjs`) — 기록된 문장 → 코드 라벨. 판정이 아니다.
2. **커버리지 스크립트** (`scripts/eval-coverage.mjs`) — 241회차의 표 넷을 전수로 분류해 세고,

3. **사고 반입** (`scripts/import-incidents.mjs`) — 운영 저장소의 규칙 근거 표를 익명화해 들여오고
   원인 단계 넷으로 나눈다.
4. **`EVAL.md`** — 네 표와 `PRD.md §8` 다섯 기준의 지금 값.
5. **`/eval` 화면** — 같은 네 표. `src/fleet/evals.mjs` 가 결과 파일 넷을 읽는다.

## 축을 왜 둘로 나눴나 — 이 슬라이스의 핵심

`PRD.md §8` 은 "회차 기록을 재생해 90% 이상 일치" 라고 적었는데 **그대로 할 수 없다.**
기록에 남은 것은 결과 문장뿐이고 그 시점의 워크스페이스·브랜치·커밋·카드가 없다. 판정을 다시
돌릴 재료 자체가 없으므로 "재생해 대조" 가 성립하지 않는다.

그래서 (가) 픽스처로 시나리오를 재생해 **일치**를 재고, (나) 기록의 사유 문장을 **분류**해 커버리지를
잰다. 둘은 다른 것을 재고, 그 사실을 `EVAL.md` 머리말에 적었다 — 축 나를 일치율이라고 부르면
"판정이 옳았다" 는 뜻으로 읽힌다.

축 나를 다시 둘로 나눈 것은 리뷰 R1 이 잡은 자리다. `workspaceState` 는 문장이 아니라 깃발
셋(`ready`·`blocked`·`waiting`)을 읽어 문장을 주면 늘 `busy` 를 돌려주고, `holdOf` 의 코드표는
**파견 보류** 사유 접두어뿐이라 착륙 막힘 20행이 전부 `other` 다. 파견 보류 사유는 `holdOf`,
착륙 막힘·사람 호출은 새 분류표. **`holdOf` 도 `workspaceState` 도 안 고쳤다.**

## 표본을 세는 단위가 둘이다 — 행과 고유 항목

`결정 필요` 328행은 **고유 항목 85개**다. 같은 항목이 답을 받을 때까지 회차마다 다시 올라오기
때문이다. 어느 쪽으로 세느냐에 따라 헛호출률이 31.8%(고유)와 50.3%(행)로 갈린다 — 둘 다 적었다.

- 행으로 세면 "얼마나 자주 사람 눈에 띄었나" 이고, 고유로 세면 "몇 가지 일을 시켰나" 다.
- `limit-hold` 는 고유 29개가 83행이 됐다. 한도 보고 하나가 평균 세 회차를 산다.

## 헛호출률이 목표를 못 넘는다 — 숨기지 않는다

**판단 31.8%(고유) · 50.3%(행). 목표는 80%.** 판단+조작으로 느슨하게 세도 63.5% · 74.1% 다.

가장 큰 몫은 `limit-hold` 83행 — 한도가 차 파견을 멈췄다는 보고인데, 초기화 시각이 지나면 저절로
풀리고 그 사이 사람이 할 것이 없다. 이것 하나를 사람 호출에서 내리면 판단 비율이 행 기준
50.3% → 67.3% 가 된다. 그래도 80%에는 못 미친다.

**판정이 갈리는 자리를 적어 둔다**: 한도 보고를 받은 사람이 "다른 에이전트로 인계할까" 를 정할
여지는 있다. 그것을 판단으로 세면 수가 달라진다. 여기서는 **인계를 플릿이 스스로 하므로**
불필요로 셌다 — 기록에 `인계 → claude` 항목이 실제로 있다(그 자체도 헛호출로 셌다: 이미 끝난
실행의 보고다).

`worker-hands`/`worker-decide` 를 가른 것은 **휴리스틱**이다(문장에 사람이 할 동작이 적혀 있나).
규칙이 아니므로 항목별 라벨을 `data/eval/coverage.json` 의 `calls.items` 에 그대로 실어 뒀다.

## 사고 표는 행 수가 사고 수가 아니다

원본 표 **30행**(리뷰 실측 때는 29행이었고 그 뒤 한 행이 늘었다) 중 제외 목록 프로젝트의 이름이
든 **1행**을 통째로 뺐고(§1), 반입한 29행 중 실제 사고는 **19건**이다. 나머지 10행은 사용자
결정·요청 4 · 점검 결과 3 · 기능 2 · 운영 결정 1. `PRD.md §9` 의 "사고 28건" 은 세지 않은 것이
섞인 수다.

원인 단계는 실행 7 · 사람 개입 설계 6 · 판정 4 · 관찰 2. 라벨은 **사람이 읽고 붙였다** — 번호로만
코드에 적고(`scripts/import-incidents.mjs` 의 `LABELS`) 근거는 반입한 원문이 진다. 표에 없는 번호는
`미분류` 로 세어 보고하므로 원본에 행이 늘면 드러난다.

**사람 개입 설계 6건 중 둘(12·16)이 헛호출이다** — 같은 항목이 회차마다 되풀이돼 사람을 부른 것.
표 3의 `limit-hold` 83행이 정확히 같은 종류라, 두 표가 같은 곳을 가리킨다. 다음에 고칠 것 1번이
여기서 나왔다.

## 익명화 — 세 번째

반입 스크립트가 읽는 `anonymize.local.json` 이 저장소에 없어서(리뷰 R11) 먼저 만들었다. 매핑
파일의 제외·치환·경로 표를 그대로 옮겼고 `incidentSource` 를 더했다. **판단이 갈리는 자리는
없었다** — 제외 목록이 이름 둘로 명확했다.

- 제외 이름이 든 행은 이름만 지우지 않고 **통째로** 뺐다. 뺀 번호를 결과 파일에 적는다.
- ssh 호스트 별칭이 한 행에 있어 `<ssh-alias>` 로 치환했다 (`ANONYMIZATION.md §2`).
- 금칙어가 하나라도 남으면 **아무것도 쓰지 않는다** — 스크립트가 그렇게 끝난다.
