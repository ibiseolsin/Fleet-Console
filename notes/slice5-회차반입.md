# 슬라이스 5 — 회차 기록 반입과 trace 뷰어 (2026-09-10)

실제 이름·경로는 여기 적지 않는다. 매핑은 로컬 전용 파일에 있다 (`ANONYMIZATION.md §5`).

```
npm run import:runs -- --from <운영 기록 폴더>   # 익명화해 data/runs/ 로
npm run import:runs -- --dry                     # 쓰지 않고 숫자만
npm run web                                      # 화면 (http://localhost:3000)
```

## 반입한 것 — 회차 241개

원본 회차 파일 10개 · 회차 253개 → **회차 241개 · 파일 10개**. 숫자 전부는
`data/import-report.md` 에 반입 스크립트가 남긴다 (손으로 쓰지 않는다).

| | |
|---|---|
| 통째로 뺀 회차 (제외 프로젝트뿐) | 12개 |
| 지운 표 행 | 107개 |
| 지운 줄 (본체 동기화·경고) | 12개 |
| 다시 센 요약 칸 | 50개 |

계획서의 함정 메모는 "파일 17개 · 회차 258개 · 제외 언급 229줄" 이었다. 실측은 **파일 17개 중
회차 파일 10개 · 회차 253개** 다. 회차가 아닌 7개는 점검 노트라 반입 대상이 아니다 —
파서가 `*-cycle.md` 만 보므로 (`src/fleet/runs.mjs` 와 같은 조건) 자연히 빠진다.

## 지우고 **다시 그린다** — 줄을 골라 지우지 않았다

회차 형식은 sp-sync 의 `renderCycleReport` 가 쓴 것이다. 반입은 그것을 파싱해 다시 그린다.
줄 단위로 지우면 남은 표 머리글·구분선이 떠돌고, 요약 숫자가 표와 어긋난 채 남는다.

익명화 규칙 셋이 그대로 코드가 됐다:

| 규칙 | 코드 |
|---|---|
| §1 제외는 **내용 자체**를 뺀다 | 제외 이름이 **한 칸이라도** 든 표 행을 통째로 지운다. 이름만 지우지 않는다 |
| §3 행을 지웠으면 요약을 다시 센다 | 착륙·파견·막힘·결정 필요를 남은 표 행에서 다시 센다 |
| §3 제외뿐인 회차는 통째로 뺀다 | 요약 줄의 프로젝트 목록이 비면 그 회차를 버린다 |
| §4 금칙어 0건 | 파일을 쓰기 **전에** 스캔한다. 하나라도 남으면 **아무것도 쓰지 않는다** |

수가 그대로인 칸은 원문을 그대로 둔다 — `파견 0(실패 1)` 처럼 괄호가 붙은 칸을 잃지 않으려고.

## 다시 셀 수 없는 칸은 **지웠다**

요약 줄에는 표 넷 밖의 칸이 가끔 붙는다(`재개 1` · `인계 1`). 표가 없어 다시 셀 수 없다.
그 칸이 있는 회차에서 제외 프로젝트의 행을 지웠다면 그 수가 어느 쪽 것인지 알 수 없다.

**칸을 지웠다** — 회차 3개에서 `인계 1` 하나씩. 확인할 수 없는 숫자를 남기는 것보다 없는 편이
§3("안 맞는 표를 그대로 두지 않는다")에 맞다. 지운 것은 `data/import-report.md` 의
"사람이 볼 것" 에 회차 번호까지 적힌다 — 조용히 사라지지 않는다.

## 설정이 없으면 반입하지 않는다

치환표·제외 목록·금칙어 패턴은 `anonymize.local.json`(git 무시)에 있다. 스크립트에 기본값을
두지 않았다 — 기본값이 있으면 설정이 없는 기계에서 **익명화를 건너뛴 기록이 조용히 커밋된다.**
설정이 없으면 그 사실을 말하고 종료 코드 2로 멈춘다.

## 화면 — Next.js 를 `web/` 에 두었다

`README.md` 가 예고한 자리 그대로다. 저장소 루트 패키지(도구·스크립트)와 분리했다 —
슬라이스 9의 배포가 `web/` 만 올리면 되고, MCP 서버가 React 를 끌고 다니지 않는다.

| 경로 | 담는 것 |
|---|---|
| `/` | `/runs` 로 보낸다 (대시보드는 슬라이스 6) |
| `/runs` | 날짜별 회차 목록 + 숫자 배지. 반입한 수(241)를 머리에 적는다 |
| `/runs/<회차>` | **관찰 → 자격 판정 → 실행** 세 단계 |

**파서를 화면용으로 복사하지 않았다.** `web/lib/runs.js` 가 `src/fleet/runs.mjs` 를 그대로
import 한다 — 도구가 내는 회차와 화면이 그리는 회차가 같은 파서에서 나와야 둘이 안 갈린다.

기록의 표 넷은 결과 종류별로 적혀 있지 회차 진행 순서가 아니다. 상세 화면이 단계에 맞춰 다시
묶는다: 관찰(프로젝트·본체 동기화·경고) → 자격 판정(막힘 · 결정 필요) → 실행(착륙 · 파견).
각 행의 사유 칸(`이유`·`내용`·`비고`·`지시`·`결과`)은 색으로 구분한다 — 도구가 내는 것도
화면이 보여주는 것도 결국 그 한 칸이다.

**표를 표로 그리지 않았다.** 회차 기록의 칸에는 한 문장씩 들어 있어 400px 에서 표는 반드시
넘친다. 행 하나를 카드 하나로 세우고, 560px 부터 라벨을 왼쪽으로 돌린다.

## 회차 주소는 파일 이름 + 순번이다

제목의 날짜·시각이 **겹친다** — 반입한 241개 중 2쌍이 같은 분이다. `runs.mjs` 에 파일 안의
순번(`seq`)과 `runSlug()` 를 더했다. 주소는 `2026-09-09-30` 꼴이고 241개가 모두 다르다.

| §3대로 요약 숫자를 다시 셌다 | 다시 센 칸 50개. 반입본 241개 전부에서 요약 숫자 = 표 행 수 (파서로 대조, 어긋난 회차 0개) |

## 다음 슬라이스가 알아야 할 것

- **`fleet_report` 는 아직 `sandbox/runs/`(픽스처)를 본다.** 화면만 `data/runs/` 를 본다.
  둘을 합칠지는 슬라이스 8(평가 재생)이 정한다 — 도구의 대상 폴더를 바꾸는 것은 이 슬라이스 밖이다.
- **승인 큐 화면(슬라이스 6)은 `web/app/approvals/` 에 붙인다.** 목록·상세가 쓰는 그릇
  (`.card` · `.rows` · `.row` · `.n`)이 `web/app/globals.css` 에 이미 있다.
- **화면은 서버 컴포넌트뿐이다.** 승인 버튼이 붙는 슬라이스 6에서 첫 클라이언트 코드가 생긴다.
  `next.config.mjs` 의 `outputFileTracingRoot` 가 저장소 루트를 가리키니 `src/fleet/*` 를 계속
  그대로 import 하면 된다.
- **비용·시간 계측(슬라이스 6)이 붙을 자리**는 회차 상세의 단계 셋 사이다. 지금은 기록에 시간이
  없다 — 회차 시각 범위로 세션 기록을 묶는 집계를 새로 만들어야 한다 (계획서 함정 메모).
- 회차를 다시 반입하면 `data/runs/` 를 통째로 지우고 다시 쓴다. 손으로 고친 것은 사라진다.
