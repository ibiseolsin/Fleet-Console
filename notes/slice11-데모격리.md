## 변경

- `FLEET_STATE_ROOT` 하나로 픽스처·승인 큐·회차 기록·에이전트 실행·SDK 세션·하루 사용량을 묶었다. 기본값은 기존 `sandbox/`다. CLI의 기존 경로도 유지한다.

## 실패와 재검증의 범위

- 처음 `npm test`는 sandbox에서 3개 실패했다. 대표 출력: `Command failed: orca.exe worktree list --json`. 로컬 앱 조회가 가능한 환경에서 455/455로 재검증했다.
- 처음 모델 검사는 `시간 상한 120초` 뒤 승인 항목이 없어 `TypeError: Cannot read properties of null (reading 'id')`로 종료했다. 로컬 실행 파일·인증 접근이 가능한 환경에서 같은 검사 전체가 통과했다.
- 첫 해시 검사는 감시 대상 `sandbox/`에 검사 로그를 쓰고 다른 검사를 병행한 탓에 `생김 slice11-test.log / 바뀜 slice11-check.log`로 실패했다. 출력을 임시 디렉터리로 옮기고 순차 실행해 sandbox 해시는 통과했다.
- 실제 홈의 전체 해시 비교는 운영 작업·훅이 동작 중이어서 `바뀜 log.txt / 바뀜 state.json`으로 실패했다. 검사 프로세스에만 별도 `USERPROFILE`을 지정해 외부 작성자가 없는 홈에서 전체 검사를 통과시켰다. 실제 홈의 전체 파일 불변은 미확인이다. 실제 홈의 플릿 락·방아쇠·회차 결과 불변은 별도 쓰기 도구 검사와 실제 모델 검사에서 통과했다. 운영 설정은 변경하지 않았다.
- 개발 서버가 살아 있는 동안 최종 빌드를 실행한 검증 간섭으로 `Cannot find module for page: /eval`과 브라우저 `Internal Server Error`가 났다. 서버를 종료한 뒤 빌드하고 프로덕션 서버로 브라우저 검사를 다시 진행했다.
