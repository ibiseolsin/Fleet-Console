# 슬라이스 6 — 승인 큐와 회차별 시간·토큰 계측 (2026-09-10)

실제 이름·경로는 여기 적지 않는다. 매핑은 로컬 전용 파일에 있다 (`ANONYMIZATION.md §5`).

```
npm run import:usage      # 플릿 로그 + 세션 기록 → data/usage/ (로컬 원본이 있어야 한다)
npm run usage:check       # 반입 결과가 회차 기록과 맞는지 (원본 없이도 돈다)
npm run web               # /approvals · /eval
npm run approve           # 같은 큐를 명령줄에서
```

## 둘을 했다

| | 어디 |
|---|---|
| 승인 큐 화면 | `web/app/approvals/` — 슬라이스 4의 `approvals.mjs` 위에 그대로 |
| 회차별 시간·토큰 | `scripts/import-usage.mjs` → `data/usage/cycles.json` → `/eval` · 회차 상세 |

## 승인 — 버튼이 아니라 **묶은 함수**가 결정을 나른다

첫 판은 버튼에 `name="decision" value="approve"` 를 달았다. 화면에서 누르면 승인이
**"결정은 approve 또는 hold 다: "** 로 튕겼다 — 폼 데이터에 그 값이 안 실려 오는 경로가 있다.

고친 모양은 `decide.bind(null, 'approve')` 를 버튼의 `formAction` 에 다는 것이다. 버튼마다
다른 함수라 값이 샐 자리가 없고, 메모 칸은 폼 하나에 그대로 둔다(버튼 둘이 같은 메모를 쓴다).

**클라이언트 컴포넌트를 만들지 않았다.** 슬라이스 5는 "승인 버튼이 붙는 슬라이스 6에서 첫
클라이언트 코드가 생긴다" 고 적었지만, 서버 액션 + 폼이면 화면은 서버 컴포넌트로만 선다.
결과는 주소줄(`?msg=`)로 돌려준다 — 자바스크립트가 꺼져 있어도 버튼이 동작한다.

**큐 화면은 `force-dynamic`.** 큐 파일은 커밋되지 않는 이 기계의 실행 기록이라, 빌드 때 구운
값을 보여주면 방금 누른 승인이 안 보인다.

## 시간 — 로그는 단계가 **끝날 때만** 한 줄을 남긴다

회차 기록에는 시간이 없다(`renderCycleReport` 가 안 적는다). 플릿 로그에는 줄마다 UTC 시각이
있어서, 회차 제목의 시각(시작)부터 보고를 파일에 붙인 줄(끝)까지가 한 회차다.

로그가 남기는 것은 **끝난 단계**뿐이라 관찰·판정을 따로 못 잰다. 그래서 구간 이름을 그것을
**끝낸 줄**의 단계로 지었다 — `파견 3분` 은 파견 줄 앞의 3분이고 거기에는 그 파견을 하기 전의
관찰·판정이 섞여 있다. 마지막 구간(마지막 실행 → 보고 쓰기)이 `관찰·기록` 이고, 아무 실행도
없던 회차는 통째로 이것이다. 단계는 다섯: 착륙 · 재개 · 인계 · 파견 · 관찰·기록.

**회차 시작이 분 단위**라 소요는 최대 59초 길게 나온다. 초 단위 시작 시각은 어디에도 없다.
이 두 한계를 보고서·화면·회차 상세 세 곳에 그대로 적었다 — 못 가른 것을 가른 척하지 않는다.

겹친 회차를 가르는 법: 프로젝트마다 회차가 따로 돌아 시간이 겹친다. 끝 줄은 **같은 회차 파일**
안에서 **시작이 그 줄보다 앞선 것 중 가장 최근**의 아직 안 짝지어진 회차에 붙인다.

## 토큰 — 세션 기록을 회차 시각 범위로 묶는다

원본은 에이전트 세션 기록(줄마다 `timestamp` · `cwd` · `message.usage`)이다. 메시지 하나는
**그 시각 이전에 시작한 회차 중 가장 최근이면서 그 프로젝트를 다룬** 회차에 붙는다.

- **`requestId` 로 중복을 거른다.** 한 요청이 여러 줄로 쪼개지고, 세션을 이어 열면 앞 대화가 새
  파일에 다시 쓰인다. 안 거르면 8할이 겹쳐 세어진다.
- **세션 내용은 한 글자도 안 읽는다** — 시각·경로·`usage` 만 본다.
- 회차 기록에 이름이 안 나오는 저장소는 `기타` 로 묶는다. 반입이 새 이름을 공개하지 않는다.
- 플릿이 다루지 않는 저장소의 세션은 어느 회차에도 안 붙는다(미귀속). 그 수를 보고서에 적는다.

익명화는 §1·§2·§3 그대로다 — 제외 프로젝트의 세션은 **폴더째** 버리고(24개), 프로젝트별은
**비중(%)만** 내며, 뺀 뒤 비중을 다시 계산한다. `usage-check` 가 "프로젝트별 절대치가 파일에
없다" 를 단언한다.

## 다음 슬라이스가 알아야 할 것

- **대시보드(`/`)는 아직 `/runs` 로 보낸다.** PRD §6 의 대시보드는 이 슬라이스 밖이었다.
- **`/eval` 은 빌드 때 구워진다**(정적). 계측 파일을 다시 반입하면 `npm run web:build` 를 다시
  돌려야 화면이 바뀐다. 승인 큐만 `force-dynamic` 이다.
- **슬라이스 7(에이전트 루프)의 trace 는 이 계측과 다른 것이다.** 여기 숫자는 *운영* 회차를
  되짚은 것이고, 루프가 남길 것은 앱 안에서 방금 돈 실행이다. 같은 화면에 섞지 않는 편이 낫다.
- **슬라이스 8의 재생 시간**은 `/eval` 의 "회차 소요" 와 같은 칸에 넣지 않는다 — 하나는 실제
  기계가 창을 띄운 시간, 하나는 판정만 다시 돌린 시간이다.
- 계측을 다시 반입하면 `data/usage/` 를 덮어쓴다. 손으로 고친 것은 사라진다.
