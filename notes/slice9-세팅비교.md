# 슬라이스 9 — 세팅 비교 실험 (2026-09-11)

실제 이름·경로는 여기 적지 않는다. 매핑은 로컬 전용 파일에 있다 (`ANONYMIZATION.md §5`).

```
npm run eval:settings   # 픽스처를 다시 만들고 동시 상한 × 재개 상한 9조합을 관찰 → data/eval/settings.json
```

## 무엇을 했나

`observeFleet` 에 세팅 두 개를 인자로 열고(`caps` · `resumeMax`), 그것을 갈아 끼워 같은 픽스처를
아홉 번 관찰하는 스크립트 하나(`scripts/eval-settings.mjs`)와 결과 파일(`data/eval/settings.json`)이다.
**판정 규칙은 하나도 안 만들었다** — 바꾼 것은 `dispatchPlan` 의 `max` 와 `resumePlan` 의 `max` 로
넘어가던 값 둘뿐이고, 표에 싣는 사유는 sp-sync 가 낸 문장 그대로다. **픽스처도 안 늘렸다.**

## 세팅이 실제로 움직이는 것은 둘뿐이다

아홉 조합을 다 재 보면 판정 대부분이 세팅과 무관하다. 움직이는 것:

| | 2 → 3 → 5 (동시 상한) | 1 → 2 → 3 (재개 상한) |
|---|---|---|
| 파견 자격 | 2 → 3 → 3 | 안 움직임 |
| `cap-project` 보류 | 1 → 0 → 0 | 안 움직임 |
| 재개 `exhausted` | 안 움직임 | 2 → 1 → 0 |
| 사람 호출 합계 | 7 → 6 → 6 | 8 → 7 → 6 (상한 2 기준) |

나머지 — `running` 4 · `deps-undone` 1 · `plan-error` 1 · `solo` 1 · `decision` 1 · 착륙 막힘 3 ·
카드 질문 대기 1 — 은 아홉 조합 전부에서 같은 수다. 상한은 **파견과 재개**를 가르고, 착륙은
유휴 판정이, 결정 필요는 계획 태그가 가른다. 그래서 사람 호출을 합계 하나로 내지 않고
**갈래 다섯으로 나눠 세고 "움직이나" 열을 붙였다** — 합계만 내면 움직이는 둘이 안 움직이는 셋에 묻힌다.

## 사람 호출을 어떻게 셌나

`PRD.md §5` 의 개입 지점을 관찰 결과에서 셀 수 있는 모양으로 옮겼다:
착륙 막힘(`workspaces[].state==='blocked'`) · 카드 질문 대기(`cards[].wait`) ·
재개 소진(`resume[].action==='exhausted'`) · 결정 필요 슬라이스(`hold==='decision'`) ·
상한 도달(`hold` 가 `cap-project`·`cap-global`).

`§5` 의 여섯째인 **충돌 해소 실패는 여기 없다** — 샌드박스에는 살아 있는 워커 세션이 없어 해소를
시도조차 하지 않는다(슬라이스 8 시나리오 9와 같은 사정).

한 워크스페이스가 두 갈래에 들 수 있다 — cobalt/slice5 는 착륙 막힘이면서 재개 소진이다.
그래서 갈래 합계와 함께 **서로 다른 대상 수**도 낸다(상한 2에서 8건/6대상, 상한 3에서 7건/5대상).

## 표본이 작다 — 늘리지 않는다 (검토 R5)

`cap-project` 로 떨어지는 슬라이스는 픽스처 전체에서 **1개**(beacon 5번)다. 그래서 상한 sweep 은
1 → 0 → 0 이고 3 → 5 는 아무것도 안 움직인다. 수가 안 는다고 픽스처를 늘리면 슬라이스 8의 시나리오
표본이 같이 바뀌므로 늘리지 않고 **표본 수를 출력과 결과 파일에 그대로 적었다**.

같은 이유로 자격이 느는 자리는 수만이 아니라 슬라이스 이름까지 낸다 —
`[beacon 4번, cobalt 2번] → [beacon 4번, beacon 5번, cobalt 2번]`. 표본이 하나면 "1이 0이 됐다" 보다
"beacon 5번이 풀렸다" 가 읽을 수 있는 사실이다.

## 재개 상한 1 은 슬라이스 8의 근거를 지운다 (검토 R4)

`resumePlan` 은 `attempts >= max` 를 카드 `wait` 검사보다 **앞에서** 본다. 그래서 재개 상한 1에서
beacon/slice3(시도 1회)이 `wait` 가 아니라 `exhausted` 가 되고, 슬라이스 8 시나리오 8(카드가 질문
대기 중)의 판정 재료가 사라진다. 세팅마다 일치표를 다시 판정하면 일치율이 판정이 아니라 세팅
탓에 흔들린다 — 그래서 **일치표는 기준 세팅(재개 상한 2)에서만 판정하고**(`scripts/eval.mjs` 그대로),
여기서는 갈래가 바뀐 사실만 적는다. 바뀌는 둘:

```
beacon/slice3 (시도 1회): exhausted → wait → wait
cobalt/slice5 (시도 2회): exhausted → exhausted → resume
```

## 에이전트 두 종 — 있는 것으로만

계획대로 픽스처 정의는 안 바꿨다. 지금 픽스처가 이미 섞어 쓰는 두 종의 갈래 차이를 내는 데까지다:
헤드리스 3개(전부 codex) · TUI 2개(claude). 갈래가 갈리는 자리는 **유휴 판정**이다 — 헤드리스는 세션
기록만으로 끝까지 갈리고, TUI 는 Orca CLI 를 부르므로 잠든 창이어야 디스크만으로 갈린다.
세팅 sweep 은 이 차이를 안 움직인다(상한은 파견·재개를, 유휴는 착륙을 가른다).

종류를 정하는 것은 `headlessOf` 이고 **계획의 `[에이전트: …]` 보다 세션 기록이 먼저다.**
cobalt/slice5 가 그 자리다 — 계획 에이전트는 `없음`(5번이 다음 단계라 현재 단계 슬라이스에 안 붙는다)인데
세션 기록에 codex 로 남아 헤드리스로 판정된다.

슬라이스 8이 `scripts/eval.mjs` 안에 두었던 "픽스처가 정의 그대로인가" 검사를 `scripts/fixture-guard.mjs`

정말로 파견·착륙하므로 그 뒤에 관찰하면 표가 조용히 달라진다. 베껴 두면 한쪽만 고쳐진다.
